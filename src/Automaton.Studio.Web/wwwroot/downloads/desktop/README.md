# Automaton Studio Desktop Downloads

This directory contains the desktop application installers and packages.

## Expected Structure

```
desktop/
├── latest/
│   ├── AutomatonStudioDesktop-win-x64-Setup.exe
│   ├── AutomatonStudioDesktop-win-x64.zip
│   ├── AutomatonStudioDesktop-win-arm64.zip
│   ├── version.json
│   ├── checksums.txt
│   └── INSTALL.md
├── v1.0.0.123/
│   └── [same structure as latest]
└── README.md (this file)
```

## Deployment Process

These files are generated by the Azure DevOps pipeline `azure-pipelines-studio-desktop.yml` and should be deployed to your hosting provider.

### Pipeline Artifacts

The pipeline generates:
- **Installer**: AutomatonStudioDesktop-win-x64-[version]-Setup.exe (NSIS installer)
- **Portable**: AutomatonStudioDesktop-win-x64-[version].zip (self-contained)
- **ARM64**: AutomatonStudioDesktop-win-arm64-[version].zip (self-contained)
- **Metadata**: version.json, checksums.txt, INSTALL.md

### Hosting Provider Deployment

1. Run the Azure pipeline to generate artifacts
2. Download the `automaton-studio-desktop-packages` artifact
3. Extract the contents to your hosting provider's downloads folder
4. Update the `latest/` directory with the new version
5. Optionally, keep versioned copies in separate directories

## File Descriptions

- **Setup.exe**: NSIS-based installer with Start Menu and Desktop shortcuts
- **ZIP files**: Self-contained portable versions, no installation required
- **version.json**: Build metadata for version checking and updates
- **checksums.txt**: SHA256 checksums for integrity verification
- **INSTALL.md**: User installation instructions

## URLs

The desktop download page expects these files to be available at:
- `/downloads/desktop/AutomatonStudioDesktop-win-x64-Setup.exe` (latest installer)
- `/downloads/desktop/AutomatonStudioDesktop-win-x64.zip` (latest x64 portable)
- `/downloads/desktop/AutomatonStudioDesktop-win-arm64.zip` (latest ARM64 portable)

## Update Process

When deploying a new version:
1. Extract new artifacts to a versioned folder (e.g., `v1.0.0.124/`)
2. Copy/symlink the new files to the `latest/` folder
3. Update the main download links if needed
4. Test download URLs to ensure they work correctly

## Maintenance

- Monitor download statistics and user feedback
- Keep at least the last 3 versions for rollback capability
- Clean up very old versions periodically to save storage space
- Ensure checksums.txt is always up to date for security
