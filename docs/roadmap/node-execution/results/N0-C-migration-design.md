## Source baseline and physical adoption map

Current source owners: `AccountStorageAllocation` owns account/project/locality; `HostedRunnerStorageLocalityResolver` and `HostedRunnerStorageLocalityAdoptionService` resolve/adopt locality; `HostedRunnerComputeReservationPolicy` counts current/pending snapshots; `RunnerWorkspaceService` owns target paths; `HostedRunnerResourceGroup` names slices. Provision/delete actions under `system-apps/automaton-infrastructure/actions/` configure/verify volumes, quotas and resource groups or remove them. `HostContainerExecutionService.Runtime.cs` and `HostContainerBuildExecutor.cs` consume volume subpaths/cgroups. `AppArchiveStorageBounds`, `AppSourceArchiveInstaller` and `AppFileStorageService` use the source write-lock seam. These mechanisms do not implement Node migration or prove any current host conforms.

Notation: H=legacy Hosted Runner ID, A=account ID, W=WebApp ID, T=target ID, C=candidate ID, O=operation ID; identifiers are illustrative placeholders, not measured production values. Vsys/Vuser are `automaton-hosted-runner-{H:N}-system` / `...-user`; R is the verified configured workspace root. Dockerfile defaults link `/automaton/workspace` to `/automaton/storage/workspace`, `/app/logs` to `/automaton/storage/logs`, home to `/automaton/storage/home` and Runner config to `/automaton/system`. Configuration and actual mount inspection override assumptions from defaults.

| Physical resource / path from source | Authority, mount and writer | Adoption rule |
| --- | --- | --- |
| Vsys mounted `/automaton/system` | A via H mapping; legacy Runner config/identity writer, RW | Retain volume and XFS charge. Quarantine legacy credentials; Node private journal/config uses a separate root-protected management store, never a tenant mount. No automatic copying of secrets. |
| Vuser mounted `/automaton/storage`; R normally its `workspace` subdirectory | A via H mapping; legacy Runner RW | Preserve volume name, mountpoint, inode ownership and project ID. Node resolves authorized subpaths, never exposes whole volume to tenant OCI. |
| `R/apps/W/targets/T/workspace/source` | A/W/T; source-edit/install/sync writer, RW under source lock | Preserve editable source and revision/hash. Block writes while taking cutover checkpoint; only current fenced owner can subsequently accept writes. |
| `R/apps/W/targets/T/artifacts/current/application` and `artifacts/candidates/C/application` | A/W/T/C; package/build/finalization writer; OCI application mount RO | Preserve immutable artifact digest and current/candidate references. Serving is selected artifact/public subtree only. Do not reinterpret source as live output. |
| Target `runtime`, `automaton` (including snapshots), `logs`, `cache`, action versions/executions | A/W/T and execution owner; legacy executor/finalizer writers | Inventory each actual subtree and retention policy. Keep private state/logs out of serving. Unsupported workflows/custom steps block migration of the host or are moved through a separately reviewed migration, never silently executed by Node. |
| `R/data/W/<validated relative path>` | A/W; application durable data, declared OCI mount RW | Preserve app data independent of target/executor. Record each consumer and mount mode; no recursive chown, relabel, deletion or implicit relocation. |
| `R/runner/deployments/W/T/O`, R cache, user-volume home/logs | A; staging/cache/legacy tools | Count actual storage and retain referenced attempts. Cleanup requires explicit owned-resource settlement and retention, not blanket retirement deletion. |
| Legacy configured scripts root, controller app data/backend/venv, source/live aliases or nonstandard mounts | Actual layout must be observed, not inferred | Record resolved backing storage and every writer. No generic `live/` fallback is assumed by current workspace source. Unknown, escaping or incompatible layout blocks adoption. |
| OCI writable layers, engine/build cache, bounded logs, tmpfs, images; route files; Node management state | Account scratch versus host-owned resources explicitly classified | Not all are inside XFS account volumes. Apply independent configured bounds and host reserves; routes have their own writer/fence. Node journal and engine storage cannot consume unbounded tenant-exempt disk. |

Required inventory manifest v1, persisted with the existing ownership-change operation: NodeId/RunnerHostId, installation, host boot ID, Docker engine identity/root/driver, inventory revision/time/hash; each A/H/W/T mapping; volume name/driver/labels, resolved mountpoint and device/inode identity; filesystem UUID/type/mount options, XFS project ID/inheritance and measured usage/hard limit; every relevant directory numeric UID/GID/mode/ACL and symlink resolution; all container IDs, image digests, effective UID/GID, mount sources/subpaths/modes, cgroup paths, restart policies and writers; source revision/hash and write-lock identity; artifacts/routes/data checkpoint references. Store evidence references/digests, not raw credentials or tenant content. Every nullable fact carries an explicit reason and blocks the gate that requires it. Dockerfile user names do not establish mounted-file numeric ownership.

Live values for **all** filesystem UUIDs, project IDs, UID/GID, mountpoints, usage, container/cgroup identities and aliases are unavailable. The map above is a source inventory template, not a completed fleet manifest. Require exhaustive discovery of unlabeled consumers and host bind mounts as well as known labeled volumes. DB/labels alone are insufficient ownership evidence.

Same-host adoption preserves `AccountStorageAllocation.StorageRunnerHostId`, filesystem UUID and project ID. Count one quota domain by `(NodeId, filesystem UUID, project ID)`, regardless of two volume names or multiple H aliases; ownership must resolve to exactly one A. Missing locality may be filled only from mutually consistent observed evidence using the existing locality authority; conflicting DB/host identity, duplicate cross-account project ownership, non-XFS quota assumptions or incomplete inheritance blocks. Read back enforcement and hard limit, check usage fits policy, and test writes to both volumes plus nested/new directories. Do not reset the project, shrink below usage or create a new empty volume to make validation pass. Different host/filesystem adoption needs a separate explicit copy/restore design and is outside initial cutover.

Source checkpointing must coordinate API editing/archive installs, Runner file transfers, builds, publishing/finalization, background cleanup and app writers. Reuse the stable adjacent source lock inode where applicable; the API lock alone does not serialize remote writers. First drain/revoke all writers, then hold the host-side source boundary lock and record source revision/hash under the ownership-change operation. Unknown writer/lock mapping blocks. Do not unlink locks during swaps. Running applications may continue only with documented data consistency semantics: application-consistent snapshot/quiesce for rollback-required data, or explicit forward-only boundary. Merely pausing API writes does not freeze a database in an OCI workload.

## Account cgroups and resource ledger

Initial adoption may retain `automaton-hosted-runner-{H:N}.slice` as a physical alias for A, with no permanent Hosted Runner process. A/AssignmentId/generation/policy own authorization and limits. Require actual cgroup v2/systemd hierarchy/controller readback and containment for every build, candidate, web/static/Action workload and descendant. Never promise that changing Docker metadata reparents a running container.

One verified existing slice can be adopted in place if it encloses all account consumers and enforces the aggregate policy. If A spans independent slices, require a verified common account ancestor with aggregate limits, or stop/recreate workloads under one selected account slice preserving data. If the hierarchy cannot be changed safely, block adoption. Do not grant the full account budget independently to each old/new slice. PID movement/reparenting of live workloads is not an initial migration technique. Preserve aliases in the manifest, not as entitlement authorities; retirement must not remove an adopted live slice.

| Ledger component | Authority / treatment |
| --- | --- |
| Host allocatable CPU cores, memory bytes, PIDs and disk bytes | Existing host/admission authority, measured capacity minus configured OS/engine/Node/proxy/telemetry/recovery reserves. Unknown/stale capacity fails closed. Node management overhead is included in host reserve. |
| Legacy reservation | Existing policy occupies Pending/Provisioning/Reprovisioning/Running and Failed with ContainerId; current/pending CPU and memory use their maximum. Preserve this conservative charge until effects are reconciled. |
| Adopted workload reservation | Transfer linkage atomically in existing admission authority, retaining original reservation/workload/root identities and physical evidence. Charge one adopted resource once, not both legacy snapshot and Node claim; no second totals ledger. |
| Build/candidate/old serving overlap | Distinct concurrently possible workloads charged additively inside A aggregate and host capacity. Never use max(old,new) for simultaneous containers. Configured per-kind caps include CPU, memory, PIDs, tmpfs, scratch and bounded logs; zero/unbounded defaults rejected. |
| Persistent storage | One domain hard quota, usage once across Vsys/Vuser/aliases. App data/artifacts/source remain charged after executor stops. Disk headroom additionally covers engine layers/images/build cache, staging and rollback checkpoints on their actual filesystem. Avoid counting a checkpoint twice if already in the domain. |
| Uncertain effect / partial cleanup | Existing reservation retained as occupancy debt with original operation and evidence; logical Lost/Cancelled/timeout is not capacity release. Conservatively reserve upper bound of effects that may still exist. |

Use existing admission locks/CAS and N0-B lock ordering. Transfer ownership and charge linkage in one transaction; retry with the stable scoped client request key **before** any workload/reservation allocation. Persist a reconciliation revision linking each physical resource to one reservation; unknown physical resources create blocking debt. Units on the wire are explicit (CPU decimal cores, memory/storage integer bytes, PID integer count); converting existing MB fields must pin the field's actual unit and checked conversion, never silently reinterpret it. Quota reports and cgroup readback are evidence, not a second entitlement source.

Example: one A has a 4-core/8-GiB account cap, serving container 2 cores/4 GiB, build 1 core/2 GiB and candidate 2 cores/4 GiB. All three need 5 cores/10 GiB, so admission waits/rejects even if old provisioning snapshots used max(old,new). A legacy alias and Node reference to the same serving container count once. An uncertain build still charges 1 core/2 GiB until settlement. These illustrative limits are not product defaults.

## Host-wide fencing and outstanding-effect settlement

Migration unit is the **whole host management authority**, including every account on that host. A privileged old Infrastructure Runner cannot remain on the host for a different account. Unsupported legacy cohorts stay on unmigrated hosts or block this host. N0-B's OS-held installation lock protects cooperating Node managers; an old privileged executor that does not honor it must be stopped and prevented from resurrecting independently.

Fence proof v1 binds MigrationOperationId, NodeId, installation, old principal/container/process identities, host boot/engine identity, inventory digest, previous and intended ownership generations, fencing action results, outstanding-effect settlement digest and verifier identity/time. Enumerate and disable every observed restart path: Docker restart policy, service/Compose supervisor, installer/repair/update job, provider/bootstrap automation and pending control-plane provisioning/deletion dispatch. Revoke legacy broker/HTTPS/tunnel/host-management credentials and remove host mutation access; verify processes and children stopped and restart prevention by isolated reboot/restart tests. All API/Worker/dispatcher versions capable of old dispatch must honor durable host Quiescing/Fenced status before cohort activation. Drain old queues/outboxes as fenced historical work, never republish into Node queues. Raw root/admin access is a trusted operational boundary: if an uncontrolled actor can restart the privileged manager, no single-owner proof is possible.

A partition, missed heartbeat, credential revocation, DB ownership update, process exit or empty container list alone is insufficient. Docker requests already submitted can complete after their client dies. Proof must cover those effects and every old mutation path, including files, cgroups, quota changes, routes and delete/provision jobs. Reboot/engine replacement, supervisor/config changes, newly discovered actor, inventory drift or unexpected effect invalidates the proof; quiesce and reverify before admission. If engine drain/settlement cannot be established, stop the engine/host in a reviewed outage procedure and reconcile after restart, or block; a timed wait is not a proof.

Outstanding-effect rows are reconciliation details of existing operations, not a new command ledger: original operation/root/StepKey/request digest and old tuple; issued/accepted/journal facts; exact engine request/resource identifiers; possible effect class; observed physical result; reservation; settlement kind/evidence/receipt; unresolved reason. Cover non-Node legacy operations with explicit legacy IDs rather than inventing Node receipts.

| Effect state | Settlement and gate |
| --- | --- |
| Queued, provably never issued | Fence old dispatch transactionally. For Node commands only, N0-B permits one CAS-linked recovery successor, same root/workload/reservation, fresh immutable tuple. Missing journal is not never-issued proof. Legacy work must use an explicitly reviewed translation or fail visibly, never automatic replay. |
| Issued/accepted create/start/build/stop/delete with uncertain engine outcome | Inspect exact identifiers plus complete resource inventory after fencing/drain. Confirm outcome or retain unresolved debt; no duplicate body. Destructive requests require evidence no delayed deletion can reach retained data. Any unsettled management effect blocks ownership activation. |
| Saved terminal / lost HTTPS receipt | Import exact original bytes/hash with N0-B recovery grant and current ReportingIncarnation; preserve original tuple. Fetch receipt through authorized recovery. Superseded/cancelled/Lost results are historical only; never overwrite new desired state. |
| Surviving legitimate OCI workload | Observe/adopt only after old management mutation paths and engine effects settle; verify mounts, policy, aggregate cgroup and ownership. It can retain physical occupancy while its old operation completes or stays Lost. No need to rerun the Action or wait forever for an impossible old callback. |
| Uncertain Action external effect | Mark logical uncertainty/Lost with historical evidence, never retry automatically. Continue tracking physical occupancy until terminated/reconciled. External business effect cannot be undone by container stop or rollback. |
| Partial cleanup, route/file/quota write or unknown actor | Reconcile exact owned resources and revisions; retain data/debt and block affected gates. Cleanup is a fresh authorized typed operation with current fences, not an old-result side effect. |

Example: epoch 4 submitted container create for O and crashed before recording its ID. Epoch 5 enters Recovering after old-manager fence; it inventories using O/workload labels and durable request evidence. If container exists, it is inspected/adopted or explicitly stopped; no second create and no second reservation. If absent but an asynchronous engine request is unresolved, cutover stays blocked. A saved epoch-4 result is imported as epoch-4 evidence by epoch 5. Same-owner restart preserves assignment generation; cutover/ownership recovery advances it. Intake retry K returns its original root before allocation even during this recovery.

## Cutover transitions and proof bundle

Extend the existing ownership-change operation with durable phases and checkpoint/evidence hashes; one stable host-scoped request claim and unique active migration per host. Account assignments and target selectors change together under stable ordered locks. Phase requests are CAS/idempotent; proof hashes refer to immutable authenticated records. Local Node activation/fence/journal records use N0-B flush/rename/directory-fsync semantics and the protected lock inode. API and host are not a distributed atomic transaction: use the following fail-closed handshake and reconciliation.

| Boundary | Durable precondition → transition / required proof | Fault injection and expected recovery |
| --- | --- | --- |
| C0: Planned → Quiescing | Authorized scope/support inventory; CAS host and all affected assignments to block new mutations/dispatch on all replicas. Persist prior selectors/policy and stable request claim. | Duplicate requests or crash after pause: same migration/root, no new allocation; reconcile pause everywhere before advancing. Existing serving may continue within policy. |
| C1: Quiescing → Settled | Drain source/app writers, reconcile operations/reservations and classify remaining engine effects; take provisional consistent storage/DB/artifact/route checkpoint and inventory hash. Remaining uncertainty prevents C2 completion. | Late accepted operation or source write invalidates checkpoint; remain paused, settle and recapture. Cancellation records intent without releasing debt. |
| C2: Settled → OldFenced | Stop/revoke old managers and prove host-wide resurrection prevention plus no outstanding management effects; revalidate/recapture the final checkpoint after fencing and settlement. Preserve data and adopted workloads. | Partition old manager after permit/Docker submit: cannot pass on timeout/revocation. If it resumes or any effect appears, invalidate proof and remain blocked. |
| C3: OldFenced → OwnershipCommitted | Node locally fsyncs Prepared/Recovering with old-manager proof and expected assignment revisions while holding host lock. API transaction CAS advances every affected assignment generation, pins manifest/charge mapping, selects Node exclusively and records proof digest; no admission yet. | Crash before CAS leaves old fenced/no active owner. Crash after CAS leaves new committed but Recovering/no new effects. Read durable receipt and reconcile; never restart old manager or decrement generation. |
| C4: OwnershipCommitted → Adopted | Fresh recovery grant/assignment read; local fsync of committed generations; import original operation evidence, bind storage/cgroups and reconcile all resources/occupancy. Recovery-only Stop/Cancel must name exact resources. | Corrupt/missing local state, stale permit/policy or boot/engine change: no tenant effects, inventory/reprove fence, new incarnation recovery if required. Old command immutable and rejected locally. |
| C5: Adopted → Verified | Read back quota/cgroup policy, source/artifact/data checks, owned route writer and private/public serving probes; aggregate admission and BYO support checks. Verify legacy Hosted process absent. Persist complete proof bundle. | Healthy container but bad route/artifact sync or policy mismatch: no deployment success/resume; repair forward or rollback while paused. |
| C6: Verified → Active | API CAS verifies current proof/assignment/policy and opens host/assignment admission; Node receives current authenticated Active state and durably enables gates. | Crash/partition between API and local enable: Node remains closed until fresh validated activation. Late old queue message produces zero mutation. Repeated resume does not create another workload. |

Host lock is held by the sole active management process; ownership transition gates serialize with all effect permits. Running inherited jobs are not managers. Route controllers/telemetry/cleanup must be explicitly classified and fenced where they mutate owned state. A route file atomically replaced is not proof that source/artifact finalization succeeded or that the proxy observed it.

Cutover bundle requires: immutable manifest/checkpoint hashes; per-account previous/new assignments and policy revisions; host fencing/resurrection test evidence; every outstanding operation settlement/debt; unique charge reconciliation; local activation/journal receipts; quota/cgroup readbacks; source/artifact integrity and data-consistency proof; route observed revision and serving probes; operator/verifier and software/schema versions. The verifier compares current facts, not merely presence of uploaded documents. N4 canary/live gates need actual isolated-host/production observations; this authored bundle template proves nothing live.

## Rollback transitions and irreversible boundaries

A binary rollback is permissible only when that binary supports the current durable schema, journal, assignment fences, storage layout and typed contracts. An old Infrastructure/Hosted binary that ignores Node fencing is **not** a safe automatic downgrade. Returning to legacy requires a reviewed compatibility ownership transfer with fresh scoped credentials, queues and dispatch gating, or restore/forward repair under outage. Never revive original principals/queues as a shortcut.

| Current boundary | Rollback action / proof | Fault injection and expected recovery |
| --- | --- | --- |
| Before C2, owner unchanged | Keep pause; settle/cancel migration effects, verify old owner still sole capable manager and checkpoints remain compatible; CAS resume original assignment. | Crash during unpause: durable phase and original generation govern; no Node effect allowed. |
| After C2, before C3 | No manager active. Restore compatible old manager only through explicit reauthorization and verified sole-owner activation; invalidate old fence proof and record new ownership-recovery generation. | Old credentials replay during restore denied; incomplete restore stays paused. |
| C3–C6 or Active | Quiesce all new mutation paths, settle new effects, checkpoint postcutover data, fence Node and prove no resurrection. Transfer to compatible replacement under higher generation with the same C3–C6 handshake. | Crash after Node fence/before replacement commit leaves no active manager; never both. Reservation/data identities survive retry. |
| Incompatible DB/journal/layout or data writes | Forward repair preferred. Coordinated restore requires approved outage, consistent DB/data/artifact/route checkpoint and explicit treatment of postcheckpoint writes/external effects. Restore must retain separate monotonic fencing authority; never roll epochs/generations backward with an old DB snapshot. | Restore crash or missing checkpoint member blocks activation; read-only verification and reconciliation before enable. No partial DB-only restore claiming success. |
| Retirement/cleanup | Retain volumes, slices, journal tombstones, historical mappings and checkpoints through configured rollback retention plus verified restore. Deletion requires its own explicit authorization and owned-resource proof. | Cleanup interruption records exact debt; no broad volume pruning or delete action with preserveVolumes=false. |

Irreversible boundaries to record before crossing: first incompatible schema/journal migration; first non-backward-compatible source/layout rewrite; first new tenant data write after checkpoint; external Action side effect; credential/key destruction that prevents old evidence verification; expiry/deletion of checkpoints, artifacts or tombstones; retained volume/data deletion; quota/project reassignment. This design performs none. Existing `RunnerWorkspaceService` describes a one-way historical layout transition; do not assert a legacy binary reads current paths. `delete-hosted-runner` removes consumers even with preserved volumes, so it is not a generic retirement/adoption primitive. App data is never removed merely because a Hosted Runner row/container retires.

These are concrete future test requirements, **not existing or executed Node tests**. Test stale generation/policy/digest and broker redelivery with zero effect calls. |
| PolicyRouteReadbackFailure | Quota/cgroup mismatch or good health with stale route/artifact: remains paused, no deployment success, retained data and reservations intact. |
| RollbackCrashBoundary / RestoreCompatibility | Exercise each rollback row, incompatible old binary, snapshot missing data, postcheckpoint writes and restored stale generation. No dual manager/data deletion; incompatible restore blocks; monotonic fence survives restore. |
| ControlPlaneOutage / Cancellation / CleanupDebt | Fresh permits fail closed; bounded existing workloads may continue. Cancel does not release physical occupancy until confirmed. Partial cleanup and journal corruption remain visible/recoverable, no blanket retry/delete. |

Evidence required before implementation consumers: independent storage/tenancy/fencing/security/operations review, approved authentication mechanism, explicit field mappings and schema compatibility. Before disposable canary: implemented tests above plus restore rehearsal and reboot fence proof. Before retained-account cutover: exhaustive live manifest, complete settlement/proof bundle, capacity/rollback headroom, declared legacy cohort and explicit production authorization. No unavailable live fact is converted into acceptance by passing unit tests.
