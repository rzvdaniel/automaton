# Frontend Design Standards

## Overview

This document defines the frontend design standards and best practices for apps generated by the AI in the Unified App + Step Generation feature. These standards ensure that generated apps are modern, responsive, accessible, and visually appealing.

---

## Required Standards (All Apps)

### 1. Responsive Design
- Works seamlessly on mobile, tablet, and desktop
- Uses mobile-first approach
- Fluid layouts that adapt to screen size
- Touch-friendly interactive elements (min 44px tap targets)

### 2. Modern CSS
- Flexbox and CSS Grid for layouts
- CSS custom properties (variables) for theming
- Avoid inline styles where possible
- Use utility-first CSS (Tailwind) for consistency

### 3. Semantic HTML
- Proper HTML5 elements: `<header>`, `<main>`, `<section>`, `<article>`, `<footer>`, `<nav>`
- Meaningful heading hierarchy (h1 ? h2 ? h3)
- Use `<button>` for actions, `<a>` for navigation
- Form elements with proper labels

### 4. Accessibility (A11y)
- Include `aria-label` attributes where needed
- Sufficient color contrast (WCAG 2.1 AA)
- Keyboard navigable
- Focus indicators visible
- Alt text for images

## Design Principles

### Visual Hierarchy
- Clear distinction between headings, body text, and captions
- Use size, weight, and color to establish hierarchy
- Primary actions should be visually prominent

### Whitespace
- Ample padding and margins for breathing room
- Consistent spacing using Tailwind's scale:
  - Small: `p-2`, `m-2`, `gap-2`
  - Medium: `p-4`, `m-4`, `gap-4`
  - Large: `p-6`, `m-6`, `gap-6`

### Depth & Elevation
- Subtle shadows for cards and modals:
  - `shadow-sm` - subtle elevation
  - `shadow-md` - moderate elevation
  - `shadow-lg` - high elevation (modals, dropdowns)
- Avoid excessive shadow usage

### Rounded Corners
- Modern, friendly feel with border radius:
  - Buttons: `rounded-lg`
  - Cards: `rounded-xl`
  - Inputs: `rounded-md`
  - Pills/badges: `rounded-full`

### Transitions & Animations
- Smooth state changes: `transition-all duration-200`
- Hover effects for interactive elements
- Loading spinners for async operations
- Avoid excessive or distracting animations

## Empty / No Data States

Always handle cases where the backend returns no content or empty data. Users should never see a blank screen.

### Empty State Template
```html
<div class="text-center py-12">
    <div class="text-slate-300 text-5xl mb-4">??</div>
    <h3 class="text-lg font-medium text-slate-600">No data available</h3>
    <p class="text-slate-400 mt-1">Data will appear here once loaded</p>
    <button onclick="loadData()" class="mt-4 text-blue-600 hover:text-blue-700 font-medium">
        ? Try again
    </button>
</div>
```

### Empty State with Icon Variations

| Context | Icon | Message |
|---------|------|---------|
| No search results | ?? | "No results found" |
| Empty list | ?? | "No items yet" |
| No data from API | ?? | "No data available" |
| Empty inbox | ?? | "No messages" |
| No files | ?? | "No files uploaded" |

### JavaScript Empty State Check
```javascript
async function loadData() {
    try {
        const result = await automatonApi.executeStep('GetDataStep', { inputs: {} });
        
        if (result.success && result.outputVariables?.success) {
            const data = JSON.parse(result.outputVariables.data_json || '{}');
            
            // Check for empty data
            if (!data || Object.keys(data).length === 0 || 
                (Array.isArray(data) && data.length === 0)) {
                showEmptyState();
                return;
            }
            
            // Render data
            renderContent(data);
        } else {
            showError(result.outputVariables?.error_message || 'Unknown error');
        }
    } catch (error) {
        showError(error.message);
    }
}

function showEmptyState() {
    document.getElementById('content').innerHTML = `
        <div class="text-center py-12">
            <div class="text-slate-300 text-5xl mb-4">??</div>
            <h3 class="text-lg font-medium text-slate-600">No data available</h3>
            <p class="text-slate-400 mt-1">The server returned no content</p>
            <button onclick="loadData()" 
                    class="mt-4 px-4 py-2 bg-blue-600 text-white rounded-lg hover:bg-blue-700 transition-colors">
                Try Again
            </button>
        </div>
    `;
}
```

### Empty State Design Principles

1. **Be clear**: Explain what's empty and why
2. **Be helpful**: Suggest what user can do next
3. **Be friendly**: Use appropriate icons and tone
4. **Be actionable**: Provide a button to retry or take action
5. **Be consistent**: Use same empty state pattern throughout app

## API Response Handling

### Response Structure

The `automatonApi.executeStep()` returns this structure **directly** (not nested under `data`):

```javascript
// Result from: const result = await automatonApi.executeStep('StepName', { inputs: {} });
{
    "success": true,                    // Step execution succeeded (boolean)
    "stepId": "833f2690-...",
    "stepName": "GetSystemMetricsStep",
    "status": "Completed",              // or "Failed"
    "runnerCount": 1,
    "executedAt": "2025-12-08T11:18:32.777Z",
    "completedAt": "2025-12-08T11:18:34.273Z",
    "error": null,                      // Error message if failed
    "outputVariables": {
        "success": true,                // Your step's success flag (native boolean)
        "error_message": "",            // Error details if failed
        "cpu_percent": 45.2,            // Native number
        "metrics": { ... }              // Native object (not stringified)
    },
    "logs": [
        "[11:18:32] Starting step execution...",
        "[Local] INFO: CPU Load: 45%",
        "[11:18:34] Execution completed. Success: True"
    ]
}
```

### Important Notes

1. **Response is DIRECT** - The result IS the data, not nested under `result.data`
2. **Check `result.success`** for API-level success (step found, runner available)
3. **Check `result.outputVariables.success`** for your step's custom success flag
4. **Output variables are native types** when Python outputs them correctly (not stringified)

### Correct Response Handling

```javascript
async function loadData() {
    try {
        // Result is DIRECT - not nested under result.data
        const result = await automatonApi.executeStep('StepName', { inputs: {} });
        
        // Check API-level success first
        if (result.success) {
            // Access output variables directly from result.outputVariables
            const outputs = result.outputVariables;
            
            // Check your step's custom success flag
            if (outputs.success) {
                // Access your data directly
                const data = outputs.metrics;      // Native object
                const cpu = outputs.cpu_percent;   // Native number
                
                if (!data || Object.keys(data).length === 0) {
                    showEmptyState();
                } else {
                    updateUI(data);
                }
            } else {
                // Step reported failure
                showError(outputs.error_message || 'Unknown error');
            }
        } else {
            // API-level failure (runner offline, step not found, etc.)
            showError(result.error || 'Request failed');
        }
    } catch (error) {
        showError(error.message);
    }
}
```

### Common Mistakes to Avoid

? **Wrong:**
```javascript
if (result.data.success) {  // Wrong! result IS the data, not nested
```
? **Correct:**
```javascript
if (result.success) {
```

? **Wrong:**
```javascript
const outputs = result.data.outputVariables;  // Wrong path
```
? **Correct:**
```javascript
const outputs = result.outputVariables;
```

### Gauge Chart
```javascript
function drawGauge(elementId, value, title, max = 100) {
    const data = google.visualization.arrayToDataTable([
        ['Label', 'Value'],
        [title, value]
    ]);
    
    const options = {
        width: 200,
        height: 200,
        redFrom: 80,
        redTo: 100,
        yellowFrom: 60,
        yellowTo: 80,
        greenFrom: 0,
        greenTo: 60,
        minorTicks: 5,
        max: max
    };
    
    const chart = new google.visualization.Gauge(
        document.getElementById(elementId)
    );
    chart.draw(data, options);
}
```

### Pie Chart
```javascript
function drawPieChart(elementId, data, title) {
    const chartData = google.visualization.arrayToDataTable(data);
    
    const options = {
        title: title,
        pieHole: 0.4, // Donut chart
        colors: ['#3b82f6', '#10b981', '#f59e0b', '#ef4444'],
        legend: { position: 'bottom' },
        chartArea: { width: '90%', height: '70%' }
    };
    
    const chart = new google.visualization.PieChart(
        document.getElementById(elementId)
    );
    chart.draw(chartData, options);
}
```

## Checklist for Generated Apps

Before finalizing an app, ensure it meets these criteria:

- [ ] **Responsive**: Test at mobile (375px), tablet (768px), desktop (1280px)
- [ ] **Accessible**: Proper labels, contrast, keyboard navigation
- [ ] **Modern styling**: Uses Tailwind CSS with Inter font
- [ ] **Loading states**: Shows feedback during async operations
- [ ] **Error handling**: Displays user-friendly error messages
- [ ] **Semantic HTML**: Uses proper HTML5 elements
- [ ] **Clean design**: Consistent spacing, colors, and typography
- [ ] **Functional**: All features work as expected

---

## When to Add More Graphics

Keep the design minimal by default. Add enhanced graphics only when:

1. **User explicitly requests**: "make it more visual", "add animations"
2. **Data visualization**: Charts, graphs, gauges for metrics
3. **Onboarding flows**: Step indicators, progress bars
4. **Dashboards**: Multiple data points benefit from visual hierarchy

Avoid:
- Decorative images without purpose
- Complex animations that slow performance
- Excessive color usage
- Heavy graphics that increase load time
