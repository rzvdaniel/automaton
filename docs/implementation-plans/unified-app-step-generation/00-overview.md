# Unified App + Backend Step Generation

## Implementation Plan Overview

This document outlines a comprehensive plan to simplify the App creation workflow in Automaton Studio by enabling **unified AI generation** of both frontend (Web App) and backend (Custom Steps/Flows) in a single operation.

---

## Current Workflow (Problem)

Users currently must perform **4 separate steps** across **3 different pages**:

```

?  CURRENT WORKFLOW (Complex, Multi-Page)                                 ?
???????????????????????????????????????????????????????????????????????????

?     ??? AI Chat ? Generate frontend HTML/CSS/JS                         ?
?                                                                         ?
?  2. StepPage.razor (Navigate away!)                                     ?
?     ??? AI Chat ? Generate backend Python/Batch code                    ?
?                                                                         ?
?  3. DesignerPage.razor (Navigate away again!)                           ?
?     ??? Create Flow ? Add the Custom Step to workflow                   ?
?                                                                         ?
?  4. Back to AppPage.razor                                               ?
?     ??? Configure automatonApi.executeFlow() calls                      ?
?                                                                         ?
???????????????????????????????????????????????????????????????????????????

**Pain Points:**
- Multiple navigation steps across different pages
- Three separate AI chat sessions
- Manual linking between App, Steps, and Flows
- Easy to forget or misconfigure connections
- Time-consuming for simple use cases

### When to Use What

| Scenario | Backend Type | API Call |
|----------|--------------|----------|
| Single API call (SendGrid, Stripe) | Step | `executeStep()` |
| Single DB operation | Step | `executeStep()` |
| Independent parallel operations | Multiple Steps | Multiple `executeStep()` |
| Sequential dependent operations | Flow | `executeFlow()` |
| Transactional multi-step | Flow | `executeFlow()` |
| Complex error handling | Flow | `executeFlow()` |

## Key Features

### Phase 1-5: Direct Step Execution (Core)

1. **Direct Step Execution API** (Phase 1 - Quick Win)
   - Add `automatonApi.executeStep()` to the SDK
   - Create `AppsStepExecutionController`
   - Users can skip Flow creation for simple single-step scenarios

2. **Backend Actions Tab** (Phase 2 - UI Enhancement)
   - New tab in `AppPage.razor` to list linked Custom Steps
   - Navigate directly to `StepPage.razor` for editing
   - Visual indicator of step status and version

3. **Unified AI Generation** (Phase 3 - Core Feature)
   - Enhanced system prompt that understands both frontend AND backend
   - AI generates Custom Steps automatically when backend logic is needed
   - Generates proper `executeStep()` calls in frontend code

4. **MCP Tools Enhancement** (Phase 4 - AI Tooling)
   - Tools for creating, saving, and linking steps from AI context
   - Auto-variable suggestion and configuration

5. **Testing & Polish** (Phase 5 - Quality)
   - End-to-end testing
   - Performance optimization
   - Documentation

### Phase 6: Flow Generation (Future - Advanced)

6. **Automatic Flow Generation** (Phase 6 - Future)
   - AI detects when multiple dependent operations are needed
   - Creates individual steps for each operation
   - Wires steps together in a Flow
   - Configures variable passing between steps
   - Generates `executeFlow()` call in frontend

## Quick Start for AI Implementation

When implementing this plan:

1. **Start with Phase 1** - Direct Step Execution API is independent and provides immediate value
2. **Phase 2 can run parallel** - UI changes don't block API work
3. **Phase 3 & 4 are core** - These enable the "one command" experience
4. **Phase 5 is essential** - Testing before production release
5. **Phase 6 is future** - Only after Phases 1-5 are stable
6. **Follow existing patterns** - Reference `CustomStepsService`, `StepSystemPromptBuilder`, and `StepMcpClient` for consistency

## User Journey Examples

### Example 1: Simple Backend (Step)
```
User: "Create a contact form that sends emails"

AI Analysis: 1 operation (send email) ? Use Step

Result:
- SendEmailStep created
- Form HTML generated with executeStep()
- Step visible in Backend Actions tab
```

### Example 2: Complex Backend (Flow) - Future
```
User: "Create registration that saves user, sends email, and logs activity"

AI Analysis: 3 operations with dependencies ? Use Flow

Result:
- CreateUserStep created
- SendWelcomeEmailStep created  
- CreateAuditLogStep created
- UserRegistrationFlow created (wires all steps)
- Form HTML generated with executeFlow()
- Flow visible in Backend Actions tab
```

### Example 3: Multiple Independent Steps
```
User: "Create a page with two buttons: one sends email, one generates PDF"

AI Analysis: 2 independent operations ? Use 2 Steps

Result:
- SendEmailStep created
- GeneratePdfStep created
- Page HTML with two buttons, each calling executeStep()
- Both steps visible in Backend Actions tab
