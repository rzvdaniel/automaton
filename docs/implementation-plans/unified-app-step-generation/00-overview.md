# Unified App + Backend Step Generation

## Implementation Plan Overview

This document outlines a comprehensive plan to simplify the App creation workflow in Automaton Studio by enabling **unified AI generation** of both frontend (Web App) and backend (Custom Steps) in a single operation.

---

## Current Workflow (Problem)

Users currently must perform **4 separate steps** across **3 different pages**:

```

?                                                                         ?
?  2. StepPage.razor (Navigate away!)                                     ?
?     ??? AI Chat ? Generate backend Python/Batch code                    ?
?                                                                         ?
?  3. DesignerPage.razor (Navigate away again!)                           ?

?  4. Back to AppPage.razor                                               ?
```

**Pain Points:**
- Multiple navigation steps across different pages
- Three separate AI chat sessions
- Manual linking between App, Steps, and Flows
- Easy to forget or misconfigure connections
- Time-consuming for simple use cases

## Key Features

### 1. **Direct Step Execution API** (Phase 1 - Quick Win)
- Add `automatonApi.executeStep()` to the SDK
- Create `AppsStepExecutionController`
- Users can skip Flow creation for simple single-step scenarios

### 2. **Backend Actions Tab** (Phase 2 - UI Enhancement)
- New tab in `AppPage.razor` to list linked Custom Steps
- Navigate directly to `StepPage.razor` for editing
- Visual indicator of step status and version

### 3. **Unified AI Generation** (Phase 3 - Core Feature)
- Enhanced system prompt that understands both frontend AND backend
- AI generates Custom Steps automatically when backend logic is needed
- Auto-links steps to the App
- Generates proper `executeStep()` calls in frontend code

### 4. **App-Step Relationship Model** (Data Layer)
- New `AppCustomSteps` junction table
- Track which steps belong to which App
- Support version tracking and update detection

## Quick Start for AI Implementation

When implementing this plan:

1. **Start with Phase 1** - Direct Step Execution API is independent and provides immediate value
2. **Phase 2 can run parallel** - UI changes don't block API work
3. **Phase 3 & 4 are core** - These enable the "one command" experience
4. **Follow existing patterns** - Reference `CustomStepsService`, `StepSystemPromptBuilder`, and `StepMcpClient` for consistency

Each phase document contains detailed file-by-file implementation instructions.
