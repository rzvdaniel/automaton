## Overview

The Flow architecture is a **workflow execution system** that allows users to create, manage, and execute automated workflows (called "Flows"). Each flow consists of multiple steps that execute sequentially, with the ability to pass data between steps using variables.

## Variable Collections

The heart of the Flow architecture is the **three-tier variable system**. Each tier serves a specific purpose in the data flow.

### 1. Variables (Runtime/Internal)

**Type:** `IDictionary<string, StepVariable>`  
**Purpose:** Internal working memory during execution  
**Visibility:** Flow-level, shared between steps  
**Populated By:** Step outputs during execution  
**Exposed:** ? NO (internal only)

```csharp
// During execution:
Step 1 ? Outputs: { "api_key": "sk-123" }
      ? Flow.Variables["api_key"] = "sk-123"

Step 2 ? Can access: Flow.Variables["api_key"]
      ? Outputs: { "raw_response": {...} }
      ? Flow.Variables["raw_response"] = {...}

Step 3 ? Can access: Flow.Variables["api_key"], Flow.Variables["raw_response"]
      ? Outputs: { "formatted_data": [...] }
      ? Flow.Variables["formatted_data"] = [...]
```

**Characteristics:**
- ? Automatically managed
- ? Grows as steps execute
- ? Accessible to all subsequent steps
- ? Not exposed to caller
- ? Not persisted after execution

**Example Variables Dictionary:**
```json
{
  "step1_output": "value1",
  "step2_output": { "data": "..." },
  "step3_output": ["item1", "item2"],
  "temp_calculation": 42,
  "intermediate_result": { }
}
```

---

### 2. InputVariables (Parameters)

**Type:** `IDictionary<string, StepVariable>`  
**Purpose:** User-defined parameters the flow accepts
**Visibility:** External interface (IN)  
**Populated By:** Caller when executing the flow  
**Exposed:** ? YES (public contract)

```csharp
// User defines in UI:
Flow.InputVariables = {
    "nytimes_api_key": {
        Name: "nytimes_api_key",
        Type: VariableType.String,
        Value: null,  // Set by caller
        Description: "API key for NYTimes API"
    },
    "max_articles": {
        Name: "max_articles",
     Type: VariableType.Number,
        Value: null,  // Set by caller
      Description: "Maximum number of articles to fetch"
  }
}

// Caller provides values:
await ExecuteFlow(flowId, new Dictionary<string, object> {
    { "nytimes_api_key", "sk-real-api-key-123" },
    { "max_articles", 10 }
});

// During execution, merged into Variables:
Flow.Variables["nytimes_api_key"] = "sk-real-api-key-123"
Flow.Variables["max_articles"] = 10

// Steps can access via Variables
```

**Characteristics:**
- ? Explicitly defined by user
- ? Type-safe (with VariableType enum)
- ? Documented (with descriptions)
- ? Reusable (same flow, different inputs)
- ? Validated before execution

**Think of it as:**
```csharp
// This Flow:
Flow.InputVariables = { "api_key", "count" }

// Is like this function:
public FlowResult Execute(string api_key, int count)
{
    // Flow logic here
}
```

---

### 3. OutputVariables (Return Values)

**Type:** `IDictionary<string, StepVariable>`  
**Purpose:** User-defined results the flow returns  
**Visibility:** External interface (OUT)  
**Populated By:** System (from Variables) before returning  
**Exposed:** ? YES (public contract)

```csharp
// User defines in UI:
Flow.OutputVariables = {
    "headlines": {
   Name: "headlines",
        Type: VariableType.Array,
   Value: null,  // Will be populated from Variables
        Description: "List of news headlines"
    },
    "article_count": {
        Name: "article_count",
Type: VariableType.Number,
        Value: null,  // Will be populated from Variables
        Description: "Total number of articles fetched"
    }
}

// After execution, populated from Variables:
Flow.OutputVariables["headlines"] = Flow.Variables["headlines"]
Flow.OutputVariables["article_count"] = Flow.Variables["article_count"]

// Caller receives:
var result = await ExecuteFlow(flowId, inputs);
var headlines = result.OutputVariables["headlines"];
var count = result.OutputVariables["article_count"];
```

**Characteristics:**
- ? Explicitly defined by user
- ? Selectively exported (not all Variables)
- ? Encapsulates internal details
- ? Stable interface (internal changes don't break callers)
- ? Type-safe results

**Think of it as:**
```csharp
// This Flow:
Flow.OutputVariables = { "headlines", "count" }

// Is like this function:
public class FlowResult
{
    public List<Article> Headlines { get; set; }
    public int Count { get; set; }
}

public FlowResult Execute(...)
{
    // Flow logic here
    return new FlowResult 
    { 
        Headlines = headlines, 
    Count = count 
    };
}
```

## Models & Conversion

### Flow ? Workflow Conversion

**Purpose:** Convert design-time model to runtime model

**Location:** `Automaton.Core.Services.FlowConvertService`

```csharp
public class FlowConvertService : IFlowConvertService<Flow>
{
    public Workflow ConvertFlow(Flow flow)
    {
    // 1. Create Workflow
        var workflow = new Workflow
 {
            Id = flow.Id,
   Name = flow.Name,
     StartupDefinitionId = flow.StartupDefinitionId
        };
   
        // 2. Copy variable collections
        workflow.Variables = flow.Variables;
     workflow.InputVariables = flow.InputVariables;
workflow.OutputVariables = flow.OutputVariables;
        
        // 3. ? CRITICAL: Merge InputVariables into Variables
        //    This makes them accessible to steps
  foreach (var inputVar in flow.InputVariables)
        {
     if (!workflow.Variables.ContainsKey(inputVar.Key))
            {
         workflow.Variables[inputVar.Key] = inputVar.Value;
    }
        }
        
        // 4. Convert Definitions
      foreach (var definition in flow.Definitions)
        {
            var workflowDefinition = new WorkflowDefinition
    {
            Id = definition.Id
 };
   
   // 5. Convert Steps (Step ? WorkflowStep)
 workflowDefinition.Steps = ConvertSteps(
         definition.Steps, 
  workflowDefinition
     );
            
 workflow.Definitions.Add(workflowDefinition);
  }
     
        return workflow;
    }
}
```

**Key Points:**
- ? Preserves all three variable collections
- ? Merges InputVariables into Variables for step access
- ? Converts steps using DI container
- ? Maintains flow structure

## Variable Resolution

### StepVariableParser

**Purpose:** Resolve variable references (`%variablename%`) to actual values

**Location:** `Automaton.Core.Models.StepVariableParser`

```csharp
public class StepVariableParser
{
    public object Parse(StepVariable variable, Workflow workflow)
    {
        var value = variable.Value?.ToString();
        
     if (string.IsNullOrEmpty(value))
       return value;

        // Pattern: %variablename%
     var pattern = @"%([^%]+)%";
        var matches = Regex.Matches(value, pattern);
   
        foreach (Match match in matches)
    {
            var varName = match.Groups[1].Value;
   
            // Look up variable in workflow
            var workflowVar = workflow.Variables.Values
    .FirstOrDefault(v => v.Name.Equals(
     varName, 
       StringComparison.OrdinalIgnoreCase));
       
            if (workflowVar != null)
        {
          // Replace %varname% with actual value
     value = value.Replace(
         match.Value, 
         workflowVar.Value?.ToString() ?? ""
 );
            }
        }
        
   return value;
    }
}
```

**Examples:**
```csharp
// Simple reference
Value: "%api_key%"
Result: "sk-123"

// Multiple references
Value: "https://api.com?key=%api_key%&count=%max_articles%"
Result: "https://api.com?key=sk-123&count=10"

// Nested in text
Value: "Using API key: %api_key%"
Result: "Using API key: sk-123"
```


## Summary

### Key Principles

1. **Separation of Concerns**
   - `InputVariables`: Contract IN
   - `Variables`: Internal state
   - `OutputVariables`: Contract OUT

2. **Encapsulation**
   - Internal variables hidden
   - Only defined outputs exposed
   - Implementation can change without breaking callers

3. **Automatic Variable Passing**
   - InputVariables ? Variables (automatic merge)
   - Steps ? Variables (automatic output storage)
   - Variables ? OutputVariables (automatic population)

4. **Name Matching**
   - Steps find InputVariables by name
   - OutputVariables find Variables by name
   - Case-insensitive matching

5. **Variable Resolution**
   - `%variablename%` syntax
   - Resolved at runtime
   - Supports chaining (step1 ? step2 ? step3)

### Architecture Benefits

? **Clean Interfaces** - Clear input/output contracts  
? **Flexibility** - Internal changes don't break callers  
? **Composability** - Flows can call sub-flows  
? **Type Safety** - VariableType enum for validation  
? **Documentation** - Descriptions for each variable  
? **Industry Standard** - Matches Azure/AWS patterns  

---

**This architecture provides a solid foundation for building complex, maintainable, and scalable workflow automation systems!** ??
