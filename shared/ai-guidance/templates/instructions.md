# Automaton Agent Instructions

This file is generated by `automaton` as the tool-neutral local guidance entrypoint. Do not edit it manually.

## Purpose

Help an AI tool work correctly in this folder as {{modeDescription}}.

## Immediate rule

Do not invent an Automaton project structure from scratch before checking local files.

## First decision

Before making app bootstrap decisions, check whether `automaton.json` exists in the project root.

- If `automaton.json` exists, treat this folder as an already linked app root and continue locally.
- If `automaton.json` does not exist and the user asked to build a new app here, run `automaton new "<app-name>"` immediately.
- If `automaton.json` does not exist and the user gave an existing app ID, run `automaton link <app-id>`.

## Read order

1. Read `.automaton/agents/skills/automaton-app/SKILL.md`.
2. Read `.automaton/agents/references/llms.txt`.
3. Read the linked files under `.automaton/agents/references/llms/` before making structure, backend, or deploy decisions.
4. Use `AGENTS.md` only as the root discovery entrypoint, not as the canonical source.

## Working defaults

- Frontend source normally lives in `frontend/`.
- Backend source, when needed, normally lives in `backend/`.
- Default to frontend-only unless the requested feature truly requires backend execution.
- When generating backend code, add a small amount of useful diagnostics around meaningful actions and errors.
- For Python controllers, prefer the standard `logging` module with a module-level logger and `logger.info(...)`, `logger.warning(...)`, and `logger.exception(...)`.
- `print(...)` is still compatible because Automaton captures stdout in Studio, but it should not be the default recommendation.
- Keep frontend console logging minimal. Prefer `console.warn(...)` and `console.error(...)` for real issues, and never log secrets or sensitive user data.
- Use `automaton validate` to inspect the local contract before deploy when needed.
- Treat `automaton deploy` success as the completion gate for app work.

## Canonical Rules

The canonical Automaton rules live in `.automaton/agents/references/`. If this wrapper conflicts with the reference files, prefer the reference files.

## Publishing Guardrail

- Do not run `automaton publish` unless the user explicitly requests publishing.
- `automaton deploy` is allowed for build verification and testing.
- Treat deploy and publish as separate operations.
- Do not leave local dev logs, test databases, temp files, or generated runtime artifacts inside the app folder before deploy.

## Compatibility

- `.automaton/agents/` is the canonical local agent guidance tree.
- `AGENTS.md` is the only default root adapter and points back to `.automaton/agents/`.
- Tool-specific adapters such as `CLAUDE.md` or `.github/copilot-instructions.md` are intentionally not generated by default.
