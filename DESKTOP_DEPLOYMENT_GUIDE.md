# Automaton Studio Desktop - Deployment Guide for Hosting Providers

This guide explains how to deploy the desktop application installers generated by the Azure DevOps pipeline to your hosting provider.

## Overview

The Azure pipeline `azure-pipelines-studio-desktop.yml` generates ready-to-deploy packages that need to be uploaded to your web server's downloads directory.

## Pipeline Output

The pipeline generates the following artifacts in the `automaton-studio-desktop-packages` artifact:

```
automaton-studio-desktop-packages/
├── AutomatonStudioDesktop-win-x64-1.0.0.123-Setup.exe    # NSIS installer
├── AutomatonStudioDesktop-win-x64-1.0.0.123.zip          # Portable x64
├── AutomatonStudioDesktop-win-arm64-1.0.0.123.zip        # Portable ARM64
├── version.json                                           # Version metadata
├── checksums.txt                                          # SHA256 checksums
└── INSTALL.md                                             # Installation instructions
```

## Deployment Steps

### 1. Download Pipeline Artifacts

After a successful pipeline run:

1. Go to your Azure DevOps project
2. Navigate to Pipelines → Runs
3. Select the latest successful run
4. Download the `automaton-studio-desktop-packages` artifact
5. Extract the ZIP file to get the deployment files

### 2. Upload to Hosting Provider

Upload the extracted files to your web server's downloads directory:

```
/wwwroot/downloads/desktop/
├── latest/                                              # Current version (symlinks or copies)
│   ├── AutomatonStudioDesktop-win-x64-Setup.exe
│   ├── AutomatonStudioDesktop-win-x64.zip
│   ├── AutomatonStudioDesktop-win-arm64.zip
│   ├── version.json
│   ├── checksums.txt
│   └── INSTALL.md
├── v1.0.0.123/                                         # Versioned backup (optional)
│   └── [same files as latest]
├── index.html                                          # Download page
├── install-desktop.ps1                                # Installation script
└── README.md                                           # Documentation
```

### 3. Update Latest Version

For each new deployment:

```bash
# Example using SSH/SCP
scp AutomatonStudioDesktop-* user@yourserver.com:/path/to/wwwroot/downloads/desktop/latest/
scp version.json checksums.txt INSTALL.md user@yourserver.com:/path/to/wwwroot/downloads/desktop/latest/

# Or using FTP/SFTP tools like FileZilla, WinSCP, etc.
```

### 4. Verify Deployment

Test that files are accessible:

- `https://yourdomain.com/downloads/desktop/latest/version.json`
- `https://yourdomain.com/downloads/desktop/AutomatonStudioDesktop-win-x64-Setup.exe`
- `https://yourdomain.com/downloads/desktop/install-desktop.ps1`

## Hosting Provider Examples

### Static Web Hosting (Netlify, Vercel, GitHub Pages)

1. Add files to your repository under `public/downloads/desktop/` or equivalent
2. Commit and push to trigger automatic deployment
3. Files will be available at your domain's `/downloads/desktop/` path

### Traditional Web Hosting (cPanel, Plesk)

1. Use File Manager or FTP to upload files
2. Place in `public_html/downloads/desktop/` or equivalent
3. Set appropriate file permissions (typically 644 for files, 755 for directories)

### Cloud Storage (AWS S3, Azure Blob, Google Cloud)

1. Upload files to your storage bucket
2. Configure public read access for the downloads
3. Optionally, set up CloudFront/CDN for better performance

### Docker/Container Hosting

Add to your Dockerfile:
```dockerfile
COPY downloads/ /app/wwwroot/downloads/
```

## Automation Options

### Option 1: Azure DevOps Release Pipeline

Add a release stage to automatically deploy artifacts:

```yaml
- stage: Deploy
  displayName: 'Deploy Desktop Packages'
  dependsOn: BuildAndPackage
  condition: and(succeeded(), eq(variables['Build.SourceBranch'], 'refs/heads/main'))
  jobs:
    - deployment: DeployDesktop
      displayName: 'Deploy to Web Server'
      environment: 'production'
      strategy:
        runOnce:
          deploy:
            steps:
              - task: FtpUpload@2
                displayName: 'Upload Desktop Packages'
                inputs:
                  credentialsOption: 'serviceEndpoint'
                  serverEndpoint: 'YourFTPConnection'
                  rootDirectory: '$(Pipeline.Workspace)/automaton-studio-desktop-packages'
                  filePatterns: '**'
                  remoteDirectory: '/downloads/desktop/latest/'
```

### Option 2: GitHub Actions

If using GitHub, add a deployment action:

```yaml
- name: Deploy to hosting provider
  uses: SamKirkland/FTP-Deploy-Action@4.3.3
  with:
    server: ${{ secrets.FTP_SERVER }}
    username: ${{ secrets.FTP_USERNAME }}
    password: ${{ secrets.FTP_PASSWORD }}
    local-dir: ./artifacts/
    server-dir: /public_html/downloads/desktop/latest/
```

### Option 3: PowerShell Script

For manual or scripted deployment:

```powershell
# deploy-desktop.ps1
param(
    [string]$ArtifactPath,
    [string]$FtpServer,
    [string]$FtpUser,
    [string]$FtpPassword
)

# Upload files via FTP
$files = Get-ChildItem $ArtifactPath
foreach ($file in $files) {
    # Upload logic here
    Write-Host "Uploading $($file.Name)"
}
```

## File Naming Convention

The pipeline uses this naming convention:

- **Installers**: `AutomatonStudioDesktop-win-{arch}-{version}-Setup.exe`
- **Portable**: `AutomatonStudioDesktop-win-{arch}-{version}.zip`
- **Metadata**: `version.json`, `checksums.txt`, `INSTALL.md`

## Download URLs

The Blazor application expects files at these URLs:

- Primary installer: `/downloads/desktop/AutomatonStudioDesktop-win-x64-Setup.exe` (latest)
- Portable x64: `/downloads/desktop/AutomatonStudioDesktop-win-x64.zip` (latest)
- Portable ARM64: `/downloads/desktop/AutomatonStudioDesktop-win-arm64.zip` (latest)
- Installation script: `/downloads/desktop/install-desktop.ps1`
- Direct download page: `/downloads/desktop/index.html`

## Versioning Strategy

### Recommended Approach:

1. **Latest Directory**: Always contains the current production version
2. **Versioned Directories**: Keep last 3-5 versions for rollback capability
3. **Cleanup**: Remove very old versions periodically

### File Structure:
```
downloads/desktop/
├── latest/           # Current version (what users download)
├── v1.0.0.123/      # Previous version
├── v1.0.0.122/      # Older version
└── v1.0.0.121/      # Oldest kept version
```

## Security Considerations

1. **Checksums**: Always upload and validate checksums.txt for file integrity
2. **HTTPS**: Ensure all download URLs use HTTPS
3. **Virus Scanning**: Consider scanning uploaded executables
4. **Access Logs**: Monitor download patterns for suspicious activity

## Monitoring and Maintenance

- **Download Statistics**: Track which versions and architectures are most popular
- **Error Monitoring**: Check for 404 errors on download URLs
- **Storage Usage**: Monitor disk space usage for download files
- **Update Notifications**: Consider implementing update checking in the application

## Troubleshooting

### Common Issues:

1. **404 Errors**: Verify file paths match the expected URLs
2. **Slow Downloads**: Consider using a CDN for large files
3. **Incomplete Uploads**: Check FTP/upload logs for transfer errors
4. **Permission Denied**: Ensure web server has read access to files

### Testing:

- Test all download links after each deployment
- Verify checksums match the uploaded files
- Test the PowerShell installation script
- Check the direct HTML download page
