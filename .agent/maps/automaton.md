# Automaton Agent Repository Map

This file is a compact navigation map for AI agents working in the Automaton repository.

Use this map before broad repository searches. Prefer targeted inspection of the files and folders listed here. If the map is insufficient, inspect the smallest additional set of files needed for the task and mention that in `AgentRuns/current/context.md` or `AgentRuns/current/result.md`.

## How agents should use this file

- Start here for repository navigation.
- Use `AGENTS.md` as the general agent entry point and project guidance.
- Use `.agent/agents/*.md` for role-specific instructions.
- Use `.agent/skills/*/SKILL.md` for domain-specific task guidance.
- Do not treat this map as exhaustive. It should guide where to look first.
- Prefer exact files listed here before running broad searches.

## Repository roots

- `.agent/` - local AI agent harness, roles, skills, and maps.
- `AgentRuns/` - local generated agent run state. This should normally be ignored by git.
- `src/` - application source code.
- `docs/` - project documentation when present.

## Agent system

### Role prompts

- `.agent/agents/orchestrator.md` - planning agent instructions.
- `.agent/agents/developer.md` - implementation agent instructions.
- `.agent/agents/reviewer.md` - review agent instructions.

### Harness scripts

- `.agent/harness/start-agent-task.ps1` - main entry point. Reads `AgentRuns/current/goal.md`, clears generated run files, selects mode, and starts the flow.
- `.agent/harness/classify-agent-scope.ps1` - lightweight classifier. Reads `goal.md`, writes `scope.json`, and writes `task.md` for small/tiny tasks.
- `.agent/harness/run-orchestrator.ps1` - runs the orchestrator. Writes `task.md` and `context.md`.
- `.agent/harness/run-developer.ps1` - runs the developer. Reads `developer-input.md`, modifies code, and writes `result.md`.
- `.agent/harness/run-reviewer.ps1` - runs the reviewer. Reads `review-input.md` and writes `review.md`.
- `.agent/harness/run-agent-loop.ps1` - loops developer/reviewer until accepted, stopped, or max iterations reached.
- `.agent/harness/prepare-developer-input.ps1` - builds compact developer input from `task.md`, `context.md`, and `review.md`.
- `.agent/harness/prepare-review-input.ps1` - builds compact reviewer input from `task.md`, `context.md`, `result.md`, git status, git diff stat, and capped git diff.
- `.agent/harness/write-agent-metrics.ps1` - extracts token usage metrics from Codex JSONL output.

### Agent run files

- `AgentRuns/current/goal.md` - user-authored goal. Preserved between runs.
- `AgentRuns/current/scope.json` - classifier output.
- `AgentRuns/current/task.md` - generated task for developer.
- `AgentRuns/current/context.md` - orchestrator context for normal tasks.
- `AgentRuns/current/developer-input.md` - compact developer input generated by harness.
- `AgentRuns/current/result.md` - developer result.
- `AgentRuns/current/review-input.md` - compact reviewer input generated by harness.
- `AgentRuns/current/review.md` - reviewer decision.
- `AgentRuns/current/*-metrics.json` - per-role token metrics.
- `AgentRuns/current/metrics.json` - aggregated token metrics.
- `AgentRuns/current/*.jsonl` - raw Codex execution logs.
- `AgentRuns/current/*-error-summary.txt` - bounded error summaries.

## Main application projects

### Studio frontend

Root:

- `src/automaton-studio-vue`

Common commands:

- `cd src/automaton-studio-vue`
- `npm run type-check`
- `npm run build`

Likely areas:

- `src/automaton-studio-vue/src/features/apps/` - app editor, app details, app store, app publishing, files, versions, preview, and runner-facing UI.
- `src/automaton-studio-vue/src/features/apps/views/` - top-level app views.
- `src/automaton-studio-vue/src/features/apps/components/` - app editor and app-specific UI components.
- `src/automaton-studio-vue/src/features/apps/services/` - frontend API/service wrappers for app operations.
- `src/automaton-studio-vue/src/features/apps/types/` - frontend TypeScript app types.

App editor core files:

- `src/automaton-studio-vue/src/features/apps/views/AppEditorView.vue` - main app editor page; coordinates app preview, files/code, versions, backend server, AI, logs, settings, and side panels.
- `src/automaton-studio-vue/src/features/apps/components/AppEditorSideNav.vue` - app editor left/inner navigation.
- `src/automaton-studio-vue/src/features/apps/components/AppEditorWorkspaceBar.vue` - app editor workspace/top-level tab bar.
- `src/automaton-studio-vue/src/features/apps/components/AppVersionHistory.vue` - app version/snapshot list and restore UI.
- `src/automaton-studio-vue/src/features/apps/services/apps.service.ts` - app service client and app file tree helpers.
- `src/automaton-studio-vue/src/features/apps/types/apps.types.ts` - app-related TypeScript types.

Use these first for tasks about:

- Develop navigation.
- App/preview page.
- Files page or file tree filtering.
- Versions page, snapshots, restore, or version metadata.
- AI Assistant panel placement in the app editor.
- Logs/backend/settings tabs in the app editor.

### Studio frontend conventions

- Keep TypeScript unions consistent across parent and child components.
- If adding a tab or nav target, update all prop/type unions that receive it.
- Prefer preserving existing UI behavior unless the task explicitly removes it.
- For frontend changes, run `npm run type-check` and `npm run build` from `src/automaton-studio-vue` when possible.

## Common feature map

### App editor navigation / Develop menu

Start with:

- `src/automaton-studio-vue/src/features/apps/views/AppEditorView.vue`
- `src/automaton-studio-vue/src/features/apps/components/AppEditorSideNav.vue`
- `src/automaton-studio-vue/src/features/apps/components/AppEditorWorkspaceBar.vue`

Then inspect:

- `src/automaton-studio-vue/src/features/apps/components/AppVersionHistory.vue` for versions-related UI.
- `src/automaton-studio-vue/src/features/apps/services/apps.service.ts` for files/version API calls.

### Files tree / file explorer

Start with:

- `src/automaton-studio-vue/src/features/apps/services/apps.service.ts`
- `src/automaton-studio-vue/src/features/apps/views/AppEditorView.vue`

Common concerns:

- Hide internal storage roots such as `versions`, `versions/...`, `live`, `live/...`, and internal metadata files where appropriate.
- Do not break scoped file tree calls if only the root tree should be filtered.
- Keep reusable tree-building behavior intact unless the task explicitly changes it.

### Versions / snapshots / restore

Start with:

- `src/automaton-studio-vue/src/features/apps/components/AppVersionHistory.vue`
- `src/automaton-studio-vue/src/features/apps/views/AppEditorView.vue`
- `src/automaton-studio-vue/src/features/apps/services/apps.service.ts`
- `src/automaton-studio-vue/src/features/apps/types/apps.types.ts`

If backend changes are required, then inspect:

- `src/Automaton.Api`
- shared app/version domain or persistence classes under `src/`.

Common concerns:

- Version restore should be confirmation-gated.
- Restore should refresh files and preview state.
- Version storage should remain internal and should not appear as normal user files.
- AI, manual, deploy, and CLI snapshots may share the same version listing UI but should have metadata identifying their source when supported.

### AI Assistant / session history

Start with:

- `src/automaton-studio-vue/src/features/apps/views/AppEditorView.vue`
- app editor AI-related components under `src/automaton-studio-vue/src/features/apps/components/`.

Common concerns:

- AI chat/session history belongs in the App/AI Assistant experience, not as the source-code Versions page.
- Do not confuse app source snapshots with AI conversation history.

### Logs / backend server / runner UI

Start with:

- `src/automaton-studio-vue/src/features/apps/views/AppEditorView.vue`
- app editor backend/log components under `src/automaton-studio-vue/src/features/apps/components/`.
- runner/API projects only if the task requires behavior changes.

## Token budget guidance for agents

- Read this map before broad repository exploration.
- For normal tasks, the orchestrator should use this map to produce concise `task.md` and `context.md`.
- Developer should prefer files listed in `context.md` and should not rediscover the whole repo.
- Reviewer should prefer `AgentRuns/current/review-input.md` and should not inspect unrelated files unless the prepared diff is insufficient.
- Keep `result.md`, `context.md`, and `review.md` concise.
- Store large logs in separate bounded files, not in `result.md` or `review.md`.

## When this map is insufficient

If a task references an area not covered here:

1. Search narrowly by feature name or symbol.
2. Inspect the smallest likely files.
3. Record the discovered files in `AgentRuns/current/context.md`.
4. Consider updating this map after the task if the area is likely to be reused.
